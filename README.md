# Slotify（智场通）校园体育场馆预约系统

基于 **微信小程序 + NestJS + Prisma + SQLite** 的智能体育场馆分时预约系统，覆盖「查看余量 → 选时段 → 选场地 → 下单支付 → 扫码核销 → 运营分析」完整业务闭环。

---

角色能力对照：

- **超级管理员（SUPER_ADMIN）**：管理员能力 + 开通/删除管理员账号 + 开发控制台。

## 三、启动方式

### 后端（Windows）

双击 `server/start-server.cmd`，自动完成：装依赖 → 生成 Prisma 客户端 → 同步表结构 → 首次运行灌演示数据 → 启动开发服务器。

手动方式：

```bash
cd server
npm install
npx prisma generate && npx prisma db push
npx ts-node prisma/seed.ts      # 首次运行导入演示数据
npm run start:dev               # 监听 127.0.0.1:3000 与局域网 IP
```

### 小程序前端

1. 微信开发者工具导入 `miniprogram/` 目录。
2. `miniprogram/config.ts` 中 `API_BASE_URL` 指向本机后端（模拟器默认 `http://127.0.0.1:3000/api`）。
3. 真机调试把 `LAN_API_BASE_URL` 改成启动日志里打印的局域网 IP。

### 测试

```bash
cd server
npm test    # 自动建独立测试库 → 推表结构 → 灌种子 → 跑 10 个 E2E 用例
```

## 四、已实现功能

### 用户侧
- 学工号密码登录、微信授权登录（mock 模式）
- 首页 GPS 定位入口、关键字搜索、按类型筛选、智能排序（推荐分/价格/余量）
- 场馆详情、馆内平面示意图
- **今日时段实时余量**（游客免登录可看，已过时段自动隐藏）
- 未来 7 天日历选日期、小时格子选时段（含单价预览）
- **场地级选场**（1 号场~N 号场，绿/灰状态，同时段同场地数据库唯一约束互斥）
- 填写学号/姓名/手机号 → 确认订单 → 15 分钟支付倒计时（服务端时间校正）
- 模拟微信支付（幂等流水，防重复扣款）
- 核销二维码/核销码、订单列表多状态筛选（待支付/待使用/已完成/退款取消）
- 取消订单自动退款（已支付）/释放名额（未支付）
- 个人中心统计（待使用/累计预约/预约时长）、消息通知（预约/支付/退款/核销提醒）

### 管理侧
- 运营大屏：今日 KPI、7 天营收趋势、场馆占比、热门时段、智能经营建议
- 实时监控：各馆当前/下一时段负荷与剩余名额，30 秒轮询
- 扫码核销（摄像头扫二维码或手输核销码）：预检 → 确认两步，**防重复核销**（提示上次核销人和时间）
- 预约监管：全馆订单多条件检索（场馆/日期/状态/关键字）
- 场地维护：新增/编辑场馆、营业时间变更预览、临时闭馆（日期区间）、一键开馆、上下架（自动取消未来预约并退款）
- 资金结算：营收/退款/净收入明细
- 热力矩阵：7 天 × 8 时段负荷分布
- **账号管理**：超级管理员开通/删除管理员账号（bcrypt 哈希存储）
- 操作审计日志：所有敏感操作留痕

### 后端工程
- JWT access token（2h）+ RefreshToken 轮换续期（30 天），退出登录吊销
- **tokenVersion 吊销机制**：删除/禁用账号立即失效其全部 token
- 事务防超卖（原子 `updateMany` 条件扣减 + 唯一约束重试）
- 订单超时未支付自动关闭并释放库存（每分钟定时任务）
- 金额一律「分」为单位 Int 存储
- 登录限流（5 分钟 10 次）、CORS 白名单、生产环境缺 JWT 密钥拒绝启动
- 手机号脱敏返回、异常统一包装（生产环境不回显内部错误）

## 五、未实现 / 待接入功能

| 功能 | 说明 | 需要什么 |
|------|------|----------|
| **真实微信支付** | 当前为 mock 支付（点按钮即成功），生产环境已禁用 | 微信商户号 + V3 API 证书，接入后替换 `orders.service.ts` 中的 MockWechatPayProvider |

| **定位逆地理编码** | 首页只显示「我的附近」，未反查真实地名 | 腾讯位置服务 key，接入后把坐标换成地名 |
| **退款策略** | 目前取消即全额退款，不支持「开场前 2 小时免费、之后扣手续费」等梯度规则 | 业务规则配置 + 部分退款金额计算 |
| **VenueSchedule 按星期排期** | 数据模型已建，可按周一~周日配置不同营业时间/价格系数 | 管理端配置界面 + 时段生成逻辑改造 |
| **尾段时段规则** | 营业时间不能被整时段整除时的尾巴（如 21:30 闭馆）目前直接丢弃 | 业务决策：保留短时段或明确丢弃 |
| **Court 独立场地表** | 目前场地号 = 1~totalCapacity，无独立场地档案（别名、维护状态） | 新建 Court 表 + 管理端维护界面 |
| **小程序上线配置** | 生产 HTTPS 域名、request 合法域名白名单 | 已备案域名 + 服务器 + 微信公众平台配置 |
| **多实例部署** | 登录限流为内存实现，多实例/重启后失效 | Redis 分布式限流与 token 黑名单 |
| **.ts/.js 双文件维护** | 小程序同时存在 TS 源码和编译 JS，需手动同步 | 统一 tsc 构建流程，或删除一份 |
