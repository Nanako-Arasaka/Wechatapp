项目简介Slotify场地预约小程序是一款基于微信云开发的场馆预约系统。用户通过扫码进入小程序，可以浏览场地信息、查看场地各日期时段实时余量、选择日期与时间段完成预约，查看个人订单，支持取消预约。管理员可以在小程序后台完成场地增删改查、查看全部预约订单、查看营收统计与结算面板。 系统主要服务于学校体育馆、活动室、社团活动场地等中小型场馆场景。1.2 开发环境前端：微信小程序原生框架后端：微信云开发（云数据库、云函数、云存储）用户标识：微信 openid开发工具：微信开发者工具1.3 项目范围✅包含：场地列表、场地详情预约、实时余量查询、我的订单、管理员场地管理、数据统计面板、预约冲突校验。 ❌本版本暂不实现：真实微信支付、消息推送、短信通知；可作为后期扩展功能。2 项目目标实现普通用户无需下载APP，扫码即可快速预约场地；实现场地时段余量实时计算，防止同一时段重复预约；提供完整订单生命周期管理：待使用、已使用、已取消、已过期；为管理员提供可视化后台，完成场地维护、订单管理、营收数据统计；具备基础权限控制，普通用户不可访问管理后台；保证预约操作原子性，避免并发预约造成超约问题。3 功能性需求3.1 非功能性需求安全性用户身份依靠微信openid，不使用前端传入的用户ID，防止伪造用户；预约、取消订单等写操作全部通过云函数完成，前端不直接写入订单集合；管理员页面必须校验openid白名单，普通用户禁止访问后台；预约采用数据库事务，防止并发场景下同一时段重复预约。易用性扫码直接进入小程序，无需注册账号，微信授权即可获取用户标识；页面操作简单，状态提示清晰；无数据时展示空状态提示。可靠性预约失败、网络异常要有友好提示；订单状态闭环，支持定时任务将过期预约自动标记为已过期。可维护性场地开放时段存储在数据库，修改无需修改前端代码；数据库集合结构清晰，便于后续扩展功能。兼容性适配主流手机微信版本。5 数据库设计微信云开发数据库，共3个集合：venues、orders、admins7.1 venues 场地集合{  "_id":"字符串，场地唯一ID",  "name":"场地名称",  "price":100,  "position":"场地位置",  "desc":"场地详细描述",  "images":["cloud://xxx/xxx.jpg"],  "timeSlots":["08:0010:00","10:0012:00"],  "enable":true}字段说明：timeSlots：该场地自定义开放时间段数组；enable：true启用，false禁用，禁用场地前端不展示。7.2 orders 订单集合{  "_id":"订单唯一ID",  "venueId":"关联venues的_id",  "userId":"用户微信openid",  "date":"20260829",  "timeSlot":"08:0010:00",  "price": 数字,  "status":"待使用 / 已使用 / 已取消 / 已过期",  "createTime":"服务器时间"}状态枚举说明：待使用：预约成功未使用；已使用：管理员标记已使用；已取消：用户取消预约，该时段释放可再次预约；已过期：预约时间已过去，定时任务自动更新。7.3 admins 管理员集合{  "openid":"管理员微信openid字符串"}8 云函数接口设计8.1 checkAndCreateOrder（预约创建订单）功能：校验时段是否占用，事务方式创建预约订单输入参数（前端传入）{  "venueId":"xxx",  "date":"20260829",  "timeSlot":"08:0010:00"}userId不在前端传入，云函数内部读取context.user.openid获取真实用户身份。返回成功：{"success":true,"orderId":"xxx"}返回失败：{"success":false,"message":"该时段已被预约"}业务逻辑：获取当前用户openid；数据库事务查询orders集合，查询条件：venueId、date、timeSlot，status不等于“已取消”；如果存在记录，返回预约失败；无占用，则事务内新增订单，状态=待使用；返回结果。8.2 cancelOrder（取消预约云函数）输入：{orderId:"xxx"} 逻辑：校验该订单属于当前登录用户，将订单status更新为已取消。8.3 getDashboardStat（管理端统计云函数）输入：无； 输出：今日收入、本月收入、总订单数、近7天收入数组，供dashboard页面渲染。可选扩展云函数：autoExpireOrder（定时触发器，自动更新过期订单）9 业务流程图用户预约流程用户扫码进入小程序首页，浏览场地列表用户点击场地卡片，进入场地详情用户选择预约日期（不可选过去日期）页面加载该日期下各个时段实时预约状态用户选择时段，点击立即预约前端调用checkAndCreateOrder云函数云函数事务校验时段是否被占用   71 已占用 → 返回失败，提示用户；   72 未占用 → 创建订单，返回成功；预约成功，用户跳转我的订单查看订单；该时段被锁定。管理员操作流程管理员访问管理页面；页面onLoad校验当前用户openid是否在admins集合；   21 非管理员：直接跳转回首页；   22 管理员：进入后台；管理员可进行场地增删改查，或查看统计面板与预约记录。10 约束与假设时间格式约定：日期统一使用YYYYMMDD字符串；时间段格式为HH:mmHH:mm；本项目不做真实支付，订单金额仅做统计展示；管理员需要手动将管理员openid录入admins集合；场地开放时段由管理员后台配置，每个场地独立配置；并发预约依赖云数据库事务保证不会重复下单；订单过期依赖定时云函数任务自动更新状态。
